# Asynchronous Video Recording Feature for Sunshine

This document describes the recording feature added to `Sunshine`.
The feature hooks into Sunshine's existing encoding pipeline, copies frames just before they are encoded for streaming, and saves them asynchronously in a separate recording pipeline.

Unlike client-side recording in Moonlight, this implementation records on the host side, before the frame is sent over the network. This makes it useful when you want to inspect the source frames generated by Sunshine itself.

## Overview

The recording feature captures frames from Sunshine's video pipeline immediately before streaming encode and saves them in one of the following formats:

- raw `YUV420P` (`.yuv`)
- `MP4` (`.mp4`)
- `MKV` (`.mkv`)

This is useful for:

- Quality analysis and comparison
- Debugging video issues
- Frame-by-frame inspection
- VMAF/PSNR quality metrics calculation

## Output Location

Recordings are written to the output path configured in `src/recorder.cpp`.

```cpp
output_dir = fs::path("the path you set/sunshine_recordings_async");
```

Each recording creates the following files depending on the selected mode:

| Mode | Files Created |
| --- | --- |
| `mkv` | `sunshine_recording_YYYYMMDD_HHMMSS.mkv` + `.csv` |
| `mp4` | `sunshine_recording_YYYYMMDD_HHMMSS.mp4` + `.csv` |
| `yuv` | `sunshine_recording_YYYYMMDD_HHMMSS.yuv` + `.yuv.meta` + `.csv` |

The `.csv` file stores the correspondence between the recorder's local frame index and Sunshine's internal frame number.

```csv
local_frame_idx,frame_nr
0,1
1,2
2,3
3,4
...
```

| Column | Description |
| --- | --- |
| `local_frame_idx` | Sequential frame index written by the recorder, starting from 0 |
| `frame_nr` | Sunshine's internal `frame_nr` value used in `encode_run()` when the frame was handed to the recorder |

## Output Format

| Format | Codec / Container | Lossless | Approximate Size at 1080p60 | Notes |
| --- | --- | --- | --- | --- |
| `mkv` | FFV1 in `.mkv` | Yes | 35-50 MB/s | Good for quality analysis with much smaller files than raw YUV |
| `mp4` | H.264 in `.mp4` | No | 2-10 MB/s | Smallest files, but lossy |
| `yuv` | Raw YUV420P in `.yuv` | Yes | ~178 MB/s | Best for exact frame inspection, but very large |

> **Note**  
> For VMAF or PSNR comparisons, `mkv` or `yuv` is recommended.  
> Even when the original captured frame format is NV12 or P010, the recorder converts it to `YUV420P` before writing it.

## Files Modified / Added

## New Files

### 1. `src/recorder.h`

Header file for the `recorder_t` class.

```cpp
namespace video {
  struct config_t;

  namespace recording {
    class recorder_t {
    public:
      recorder_t(const recorder_t &) = delete;
      recorder_t &operator=(const recorder_t &) = delete;

      ~recorder_t();

      static std::shared_ptr<recorder_t> create_from_env(const config_t &config);

      bool enqueue_frame(const AVFrame *frame, int64_t frame_index);

    private:
      recorder_t() = default;

      struct impl_t;
      std::unique_ptr<impl_t> impl;
    };
  }  // namespace recording
}  // namespace video
```

Key features:

- Defines `recorder_t` as the public interface for Sunshine-side recording
- Provides `create_from_env(const config_t &config)` to construct a recorder from Sunshine configuration
- Provides `enqueue_frame(const AVFrame *frame, int64_t frame_index)` so the encoding pipeline can hand frames to the recorder
- Deletes copy construction and copy assignment to prevent accidental duplication of recorder state
- Hides implementation details behind `impl_t` using a Pimpl-style structure
- Keeps the header minimal while leaving queueing, thread management, conversion, and file output in `recorder.cpp`

### 2. `src/recorder.cpp`

Implementation of the `recorder_t` class.

Key functionality:

- **Output format selection**  
  Chooses `yuv`, `mp4`, or `mkv` output based on `recording_format`

- **Frame cloning before recording**  
  Clones the source `AVFrame` with `clone_frame_for_queue()` before queueing it, rather than holding a pointer to the streaming frame

- **Hardware frame handling**  
  Detects hardware-backed frames and uses `av_hwframe_transfer_data()` when a GPU-to-CPU transfer is required

- **Pixel format conversion**  
  Uses `swscale` to convert input frames to `YUV420P` before writing

- **Asynchronous recording pipeline**  
  Maintains an internal queue and worker thread so recording is performed separately from the streaming path

- **Raw YUV output**  
  Writes the Y, U, and V planes directly when the output mode is `yuv`

- **Container output via FFmpeg**  
  Launches `ffmpeg` as a child process and streams raw video into it for `mp4` and `mkv` output

- **Metadata and CSV generation**  
  Generates `.yuv.meta` for raw recordings and writes `local_frame_idx` / `frame_nr` pairs into a `.csv` file

- **Queue overflow handling**  
  Drops frames if the recording queue is full, and optionally terminates Sunshine when `recording_stop_on_drop` is enabled

- **Recording lifecycle management**  
  Creates the output directory, opens files, allocates conversion buffers, manages the worker thread, and finalizes output on shutdown

3. Adds a helper that forwards the current frame to the recorder.

```cpp
void enqueue_recording_frame(
  const std::shared_ptr<recording::recorder_t> &recorder,
  encode_session_t &session,
  int64_t frame_nr
) {
  if (!recorder) {
    return;
  }

  auto frame = session.record_frame();
  if (!frame) {
    return;
  }

  if (!recorder->enqueue_frame(frame, frame_nr)) {
    BOOST_LOG(warning) << "recorder: failed to enqueue frame " << frame_nr;
  }
}
```

4. Sends the frame to the recorder immediately before streaming encode in the asynchronous path.

```cpp
enqueue_recording_frame(recorder, *session, frame_nr);

if (encode(frame_nr++, *session, packets, channel_data, frame_timestamp)) {
  BOOST_LOG(error) << "Could not encode video packet"sv;
  return;
}
```

5. Sends the frame to the recorder immediately before streaming encode in the synchronous path.

```cpp
enqueue_recording_frame(ctx->recorder, *pos->session, ctx->frame_nr);

if (encode(ctx->frame_nr++, *pos->session, ctx->packets, ctx->channel_data, frame_timestamp)) {
  BOOST_LOG(error) << "Could not encode video packet"sv;
  ctx->shutdown_event->raise(true);
  continue;
}
```

## Converting YUV to MP4

After recording, convert the raw YUV file to MP4 using FFmpeg:

```bash
ffmpeg -f rawvideo -pix_fmt yuv420p -s 1920x1080 -r 60 \
    -i "recorded_session/moonlight_recording_YYYYMMDD_hhmmss.yuv" \
    -c:v libx264 -pix_fmt yuv420p -crf 18 \
    "output.mp4"
```

Parameters:

- `-s WIDTHxHEIGHT` - video resolution
- `-r FPS` - frame rate
- `-crf 18` - quality target for H.264 output

Check the `.meta` file for the exact width, height, and frame rate.

## Storage Requirements

Raw YUV420P files are uncompressed:

- **1080p60**: ~180 MB/second (~10.8 GB/minute)
- **720p60**: ~80 MB/second (~4.8 GB/minute)
- **4K60**: ~720 MB/second (~43 GB/minute)

Typical compressed output sizes:

- **FFV1 / MKV at 1080p60**: about 35-50 MB/s
- **MP4 / H.264 at 1080p60**: about 2-10 MB/s

## Running

After building, run:

```bash
XDG_CONFIG_HOME=~/config ./build/sunshine
```

If you already have another Sunshine config directory, specify a separate config directory.

**CLI options:**

You can choose output formas and whether Sunshine is stopped when happening a frame drop or not.

| CLI | Description |
| --- | --- |
| `--recording-format=<yuv/mp4/mkv> `| Choose the recorder output format. Default: `yuv` |
| `--recording-stop-on-drop` | Stop Sunshine if the recorder drops a frame because the queue is full. Default: off |
| `--no-recording-stop-on-drop` | Keep Sunshine running even if the recorder drops a frame. This is the default behavior |

## Note

At certain resolutions of the Sunshine host PC and recording resolutions, colors in both the Sunshine recording data and the Moonlight display/recorded output may be different from the original.

**Example:**
- resolution of the Sunshine host PC:**1680×1050 (16:10)**
 - Colors may be incorrect at 1080p, 2160p (4K), 2520p, and 4320p.
- resolution of the Sunshine host PC:**1920×1080 (16:9)**
 - it works correctly
